# 英文阅读助手 · Obsidian

为普通英文 Markdown 打开独立阅读页：意群分组、主干提示、选词双链、摘录手札与 Focus Questions。分析不改原文；只有主动标词才写入双链，手札保存为独立 Markdown。

当前版本 **0.7.1**。已在 Windows / Obsidian 1.13.7 验证；桌面插件，暂未验证 macOS、Linux，不支持移动端。当前通过手动安装使用，尚未提交 Obsidian 社区插件目录。

## 阅读与记录

- 用命令「为当前文章打开阅读助手」或左侧书本按钮打开当前文章。
- 点击「分析文章」启动本地英语句法分析；意群和谓语提示可以分别开关。
- 默认「阅读主干」突出主句谓语，从句谓语轻提示，非谓语保持普通正文；选中句中一词后点「分析当前句」查看三类语法提示，Esc 返回。下拉框可切到全文「完整分析」。标题保留自然排版。
- 连续「摘录选文」可把多段证据放进同一篇手札；每条右下角小叉取消单条，「取消全部摘录」一次清空，文字保留。「新手札」暂存当前文字并开始独立记录。
- 手札支持 Markdown 原样保存与预览，包括标题、加粗、斜体、列表和双链；Ctrl+B / Ctrl+I 可插入格式。展开「已保存手札」后可预览、定位每条摘录，或点「编辑这条手札」载入同一阅读侧栏，再点「更新这条手札」更新原记录，不新开窗格、不追加副本。已有未保存草稿先暂存；退出编辑或重开阅读页后可继续。
- 选中英文单词或最多三个词的短语，点「标为双链」，直接写入原文并继续阅读；可连续标记和逐次「撤销标词」。也可给对应 Obsidian 命令绑定快捷键。词卡不会自动打开或创建。
- 双击或双向拖选后，连续按两次同一种中括号／大括号（`[[`、`]]`、`{{`、`}}`）也可标词；自动去掉选区首尾空白。快捷操作仅作用于阅读选区，不接管札记输入框。
- 原有双链和刚标记的双链均支持 Obsidian 原生页面预览，别名、标题和块引用保留。默认 Ctrl／Command＋悬停预览，可在核心插件「页面预览」的「英文阅读助手」来源中调整；需要启用页面预览，未创建目标的链接没有笔记正文可预览。普通点击打开目标，Ctrl／Command 点击或中键新建标签页，Ctrl／Command＋Alt 点击分栏。
- Ctrl+F / Command+F 打开页内搜索，Enter / Shift+Enter 切换匹配，Esc 关闭。搜索框沿用工具栏的中性色、图标及版心，平时隐藏。
- 首次向下滚动隐藏说明与普通状态，保留功能键和阅读目标；意群首尾空白不铺底色，各色块以小间隙分开，标点后的意群也有间隙，不插入文本字符。段首带句末标点的短粗体标题单独占行，显示调整不写回原文。
- 标词保留原有显示和格式、阅读位置及草稿，分析缓存直接复用。原文发生其他编辑时仍需刷新。已有链接可正常点击；代码、公式、嵌入、已有链接和无法可靠映射的复杂选区拒绝写入。
- 顶部「阅读目标」可以收起、自己填写或从已有问题中选择；「设为目标」不打断正文阅读，「写回答」进入手札，清除目标不会删除答案。
- 正式手札按文章保存到 `Notes/reading-notes/`；包含来源链接、问题、摘录及自己的文字。卸载插件后仍可读。

## 深浅配色

下面是早期版本的布局示意；0.6.0 的实际颜色与间隙规则见本节表格。

![早期日间布局](docs/reading-light.png)
![早期夜间布局](docs/reading-dark.png)

意群使用青绿与暖沙底色交替，以色块间隙区分分组。主句谓语使用清晰蓝色，深色主题为亮天蓝；从句用较柔和的灰蓝。主干阅读时非谓语按正文呈现，展开分析时再用金棕色与虚线显示。背景负责分组，字重和线型表达主次；间隙不写入原文或摘录。

| 检查 | 日间 | 夜间 |
| --- | --- | --- |
| 青绿／暖沙意群底色 | `#e4f2ed` / `#f7edcf` | `#25423f` / `#48402d` |
| 正文及三类动词文字的最低对比度 | 5.53:1 | 5.94:1 |
| 主句谓语与两档底色的最低对比度 | 5.53:1 | 6.22:1 |

根据深色阅读反馈，以两种克制的冷暖底色代替纯灰层次；背景、强调和正文继续分层，间隙保留不依赖色相的边界。设计依据见 [配色设计说明](docs/color-design.md)。文字对比度按 WCAG 相对亮度公式计算，超过 4.5:1；这些数值不代表阅读舒适度，自定义主题仍需实测。

## 本地安装

需要桌面版 Obsidian、Python 3.13，以及测试时使用的 Node.js 22 或更新版本。spaCy 及模型只在本地运行，不调用聊天模型或云端 API。

1. 克隆项目，在项目根目录创建 Python 环境并安装固定依赖：

   ```powershell
   python -m venv .runtime
   .runtime/Scripts/python.exe -m pip install -r plugin/requirements.txt
   .runtime/Scripts/python.exe plugin/check.py
   ```

2. 新建 `sync.local.json`，填写自己的绝对路径。这个文件已被 Git 忽略：

   ```json
   {
     "vault": "C:/path/to/your-vault",
     "python": "C:/path/to/this-project/.runtime/Scripts/python.exe"
   }
   ```

3. 执行 `python scripts/sync.py --check` 查看目标，再执行 `python scripts/sync.py` 安装。在 Obsidian 社区插件设置里启用「英文阅读助手」。已有同名且不同的插件文件会被拒绝覆盖，应先比较并保留自己的修改。

运行环境路径写入安装目录内的本机 `runtime.json`。没有这个配置时，插件尝试使用安装目录下 `.runtime/Scripts/python.exe`（Windows）或 `.runtime/bin/python`。Python 暂不可用时，普通阅读与手札仍能使用，分析会报告错误。

`focus-questions.json` 是可选的本机题库，不随本仓库分发，也不会被同步命令覆盖。没有题库时从正文提取已有问题；没有现成问题则提供明确标注的规则模板题，不冒充 AI 深度提问。题库格式示例见 [开发说明](docs/development.md)。

## 开发与同步

本仓库是开发源。`plugin/` 下修改完成后，用以下检查和同步流程更新实际使用的插件：

```powershell
node plugin/check.js
python plugin/check-colors.py
python scripts/check-sync.py
.runtime/Scripts/python.exe plugin/check.py
python scripts/sync.py --check
python scripts/sync.py --reload
```

`--reload` 需要已启用的插件、正在运行的 Obsidian 及可用的 Obsidian CLI。在 `sync.local.json` 加入 `obsidian`（CLI 绝对路径）和 `vaultName`（库名）。如需同时维护库内源码镜像，可加 `mirror`，值为相对 vault 的目录，例如 `Development/english-reading/plugin`。

同步只更新明确列出的代码文件，同时核对源码、镜像和安装文件哈希。目标文件在上次同步后被其他人改动时，整次同步会在写入前停止；不会悄悄覆盖。每次更新留本机备份，失败时恢复本次已覆盖的文件。`data.json`、分析缓存和本机题库不在同步名单内。它是开发源到使用端的单向同步，不是后台监听，也不会自动推送 GitHub。

更多说明见 [开发说明](docs/development.md) 和 [更新记录](CHANGELOG.md)。

## 已知边界

分析采用 spaCy `en_core_web_sm` 加规则，复杂长句、省略、动名词和分词形容词可能误判，不能作为考试判分依据。意群划分也没有唯一标准。

分组以连续理解为目标：短从句、短名单与动词链保持完整，长结构可以按动作和补充信息逐步展开。不会为了固定词数强制切组或跨从句合并；通用规则也不能识别所有固定搭配。常见的年份加 B.C. 等缩写后句界会辅助修正，歧义文本仍可能误判。规则与两个长度阈值见开发说明。

标词用原生 Markdown 渲染验证所选位置，写前再次核对源文；发生并发改动时拒绝覆盖。撤销历史保留在当前阅读页，刷新或关闭后结束；已有双链仍保存在原文。

新词链接目标转小写，原句大小写用显示别名保留，例如 `[[reading|Reading]]`；不自动猜词根或把屈折词归并到词典词头。现有词卡优先匹配相同词头，其他生词采集工具应读取链接目标而非显示文字。插件不查词、不设复习等级、不批量改词卡。

数学、代码和嵌入文件不参与分析。标记 `sensitive: true` 或 `scope: skip/meta` 的笔记拒绝读取正文。引文改动或重复到无法唯一定位时会提示核对。未保存草稿保存在插件本机数据中，长期留存仍应点击「保存手札」。
